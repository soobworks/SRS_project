# Error Fixing Process

아래 7단계를 순서대로 수행하고, 각 단계의 결과를 짧게 요약해 보고한다.

## Step 1: 현상 정의
- 관찰된 증상을 명확하게 기술한다.
- 재현 조건, 에러 메시지 원문, 스택트레이스를 그대로 옮긴다.

## Step 2: 맥락·범위 탐색
- 관련 파일, 데이터 흐름, 함수 호출 경로를 지도화한다.
- `Grep`/`Glob`으로 연관 심볼과 사용처를 확인한다.

## Step 3: 문제 핵심 특정
- 근본 원인을 증거 기반으로 좁혀 특정한다.
- 가설이 여러 개라면 각각의 근거와 반증을 나열한다.

## Step 4: 중급 개발자 눈높이 요약
- 전문용어를 최소화하고 쉬운 언어로 설명한다.
- "무엇이 왜 잘못되었는가"를 한 문단으로 요약한다.

## Step 5: 수정 포인트 강조
- 수정이 필요한 부분과 이유를 목록화한다.
- 각 포인트에 파일:라인 위치를 명시한다.

## Step 6: 코드 수정 수행
- 원저자의 의도를 보존하며 깔끔하게 수정한다.
- 불필요한 리팩터링을 같이 섞지 않는다(한 번에 한 가지 일).

## Step 7: 후속 개선 제안
- 테스트 추가, 로깅 보강, 리팩터링 등 후속 개선을 제안한다.
- 당장 반영하지는 않고 별도 작업으로 제시한다.

## 이 프로젝트 특화 확인
- `domain/judgment/` 관련 버그라면 §3 절대 규칙(총점 금지, 4상태 오분류 금지)을 먼저 의심한다 — 스킬 `304-judgment-domain-rules` 또는 `judgment-engine` 서브에이전트로 위임을 고려한다.
- 커넥션·마이그레이션 관련 에러라면 `DATABASE_URL`/`DIRECT_URL` 혼용을 먼저 의심한다 — 스킬 `302-data-access-rules` 참조.
