# AI 통합 규칙

## 먼저 확인할 것 — 이 기능은 기본적으로 꺼져 있다

이 프로젝트의 핵심 기능(5분류 판정, 조건 완화 시뮬레이션, 양보 문장 생성)은 **LLM 없이 결정론적 로직만으로 완결된다.** `CompromiseSentenceGenerator`(`domain/compromise/sentence-generator.ts`)는 순수 템플릿 함수이며 외부 API를 호출하지 않는다(SRS_V0_9.md §7.1).

Vercel AI SDK + Gemini는 **§7이 준비해 둔 확장 지점**이지 지금 실행되는 경로가 아니다. "LLM으로 문장을 더 자연스럽게 만들자"는 제안이 나오면, 먼저 이게 정말 필요한 확장인지(요청/승인 필요) 확인한다 — 조용히 기본 경로를 LLM 호출로 바꾸지 않는다.

## §7 확장을 실제로 켤 때 지켜야 할 것

- 모델 ID는 **환경 변수(`AI_MODEL_ID`)에서만** 온다. 코드에 `"gemini-1.5-flash"` 같은 상수를 두지 않는다(C-TEC-006).
- `@ai-sdk/google`을 다른 `@ai-sdk/*` 프로바이더로 교체해도 `generateText()` 호출 코드가 바뀌지 않아야 한다 — 이것이 C-TEC-006이 요구하는 "SDK 표준 인터페이스 준수"다.
- **Gemini 호출이 실패하거나 지연되면 결정론적 템플릿 경로로 즉시 폴백한다**(REQ-NF-009) — "빈 화면 금지" 원칙과 동일하게, 사용자 요청을 막지 않는다.
- 타임아웃을 건다. LLM이 멈추면 사용자 요청이 함께 멈춘다.
- 별도 Python 오케스트레이션 서버(LangChain 서버 등)를 두지 않는다 — Next.js 내부에서 Vercel AI SDK로 직접 호출한다(C-TEC-005).

## 지켜야 할 것 (구조화 출력을 쓸 경우)

- `generateText({ model, output: Output.object({ schema }) })`를 쓴다.
- 스키마 검증에 실패한 응답은 버린다. 부분 파싱해서 쓰지 않는다.

## 이 프로젝트에는 없는 것

참고로 삼은 다른 프로젝트(모임 장소 추천 등)의 "2단 파싱"(결정론 파서 → LLM 폴백) 패턴은 이 프로젝트에는 없다 — 우리의 자연어 파싱 대상 자체가 존재하지 않는다(조건 입력은 폼 기반, §9.1). 이 스킬을 다른 프로젝트의 파싱 캐시 히트율 기준과 혼동하지 않는다.
