# PROJECT OVERVIEW: 같이보기

## Vision

네이버 부동산의 관심매물 저장 이후 구간에서, 함께 집을 구하는 2인이 겪는 "이견 조율"을 자동화한다. **완벽한 매물이 아니라 둘 다 받아들일 수 있는 매물을 찾도록 돕는다.** 총점·순위로 하나의 정답을 강요하지 않고, 5분류 판정과 조건 완화 협상으로 의사결정을 구조화하는 것이 이 제품의 차별점이다.

## Core Features

- **조건 입력** — 예산·통근·선호를 개인별로 받는다.
- **판정 엔진** — 개인별 5분류(충족/미충족/계산불가/확인필요/해당없음) 판정 → A·B 종합 3분류 그룹화.
- **2라운드 매칭(North Star)** — 균형 잡힌 후보를 골라 양쪽에 공평하게 비교 제시한다.
- **조건 완화 협상** — 완화 시뮬레이션 → 양보 문장 생성 → 완화 제안 발신·응답.
- **(1-B) 현장 기록** — 중개사 질문·답변, 방문 후 기록.

## Target Audience

- **Primary:** 함께 집을 구하는 2인(커플·룸메이트 등).
- 이 기능은 네이버 부동산의 기존 매물 탐색 흐름 **이후** 단계에 붙는다 — 매물 검색 자체는 범위 밖.

## Project Goals & Success Metrics

권위 있는 목표는 SRS에 있다. 여기 적은 것은 개발 판단에 자주 쓰이는 요약이다.

- **North Star** — 2라운드 매칭(`V-001`)이 1-A(핵심 가설 검증) 종료 게이트다.
- **판정 정확성** — 4개 상태(미충족/계산불가/확인필요/해당없음)의 오분류가 이 프로젝트에서 가장 치명적인 버그 유형이다.
- **범위 규율** — MVP 범위는 확정됐다(`SRS_V0_9.md` §11 1-A/1-B). 없는 기능을 만들지 않는다.

## Project Philosophy

- **총점을 매기지 않는다.** 판정 결과를 합산·가중치화해 단일 스코어로 만드는 코드는 어떤 형태로도 작성하지 않는다.
- **문서가 먼저다.** 요구사항은 SRS, 태스크별 할 일은 `SRS_project/tasks/v2/{Task ID}-*.md`에 있다. 코드가 문서와 어긋나면 무엇이 옳은지 먼저 정한다.
- **AC 없는 완료는 없다.** 모든 기능 Task는 TEST 컴패니언과 쌍을 이룬다.
