## 🧪 Acceptance Criteria (BDD/GWT)
Scenario 1: 정상 후보 구성 (원 SRS AC-01-01)
- Given: A가 "같이 고르기"에 진입한 상태
- When: 관심매물 중 1~5개를 선택함
- Then: 선택한 매물 ID만 포함한 공유 객체 초안을 구성한다(후보 상한 5개).

Scenario 2: 6개째 차단 (원 SRS AC-01-02, 경계)
- Given: 이미 5개가 선택된 상태
- When: A가 6개째 매물을 추가하려 함
- Then: 해당 매물을 초안에 추가하지 않고 최대 5개 제한을 표시한다(6개째 추가 성공 0건).

## ⚙️ Technical & Non-Functional Constraints
- LIM-01, `decisions` G5: 매물 데이터는 필요한 필드만 읽고 쓰지 않는다(SharedSpace/ListingRef에 원본 매물 데이터를 복제 저장하지 않음)
- LIM-10: 후보 상한 5개는 스키마 제약이 아니라 애플리케이션 레벨에서 강제(TASK-000의 Prisma 스키마 그대로)
