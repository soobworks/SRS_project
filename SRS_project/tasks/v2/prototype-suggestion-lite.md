> **테스트 2건을 뺀 것에 대해** — 상위 문서 §9.1은 이 둘을 "뺄 수 없다"고 썼다. 라이트 범위는 그와 **다른 트레이드오프를 의도적으로 택한 것**이다. 자동 검증이 빠진 자리는 두 가지로 메운다. ① `V-002`를 **가장 먼저** 만들고 총점·추천배지 prop을 컴포넌트 API에 **아예 넣지 않는다** — prop이 없으면 테스트가 없어도 렌더할 방법이 없다(구조적 방어가 테스트보다 앞선다). ② §7의 수동 체크리스트를 매 스텝 끝에 돌린다.

### 1.1 빼지 않은 것 — `schema.prisma`와 `prisma generate`

DB를 안 쓰는데 Prisma 스키마는 남겼다. 이유가 있다.

- `C-001`(데이터 계약)은 Prisma가 생성한 모델 타입을 `import type { ... } from "@prisma/client"`로 **재노출하는 구조**다. 여기서 타입을 손으로 따로 만들면 나중에 전부 재작업이 된다 — "이후 개발을 이어가는 용도"라는 목적 자체가 깨진다.
- **`prisma generate`는 DB에 연결하지 않는다.** `schema.prisma`를 읽어 클라이언트 타입만 만든다. `DATABASE_URL`은 형식만 맞는 더미 값이면 되고, Docker도 Supabase 프로젝트도 필요 없다.
- `schema.prisma` 작성은 `SRS_V0_9.md` §6.2 원문을 그대로 옮기는 기계적 작업이다.

**연결(`migrate dev`)만 빼고 타입 생성은 남긴다** — 이것이 라이트 범위의 핵심 설계다.

## 5. 시나리오 스위처 — 신규 산출물 2건째

> ⚠️ 상위 문서 §6.2의 판정 픽스처에 이어 **이 문서가 제안하는 두 번째이자 마지막 신규 산출물**이다. 기능이 아니라 **폐기 예정 프로토타입 장치**임을 명시한다.

- **파일:** `lib/dev/scenarios.ts`
- **문제:** 상위 문서 §5.1의 화면 상태 매트릭스는 판정 결과만 6가지 상태(둘 다 충족 / 한쪽만 / 둘 다 불충족 / 확인 필요 / 계산 불가 / 해당 없음)를 요구한다. 픽스처를 손으로 갈아 끼우며 확인하면 느리고, 확인 안 된 상태가 조용히 남는다.
- **해결:** 픽스처를 이름 붙인 시나리오로 묶고 URL 쿼리로 전환한다.

```
/spaces/demo/judgments?state=A-13        ← 3분류 · 확인 필요 배지 · 계산 불가
/spaces/demo/judgments?state=A-12        ← 1인 빈 경로
/spaces/demo/judgments?state=A-13b       ← 전부 불충족, 한 조건 완화로 회복 가능
/spaces/demo/judgments?state=A-13b-2     ← 회복 불가 → 재탐색 필터
/spaces/demo/judgments?state=B-05        ← B의 첫 결과(모바일)
/spaces/demo/listings/L-001?state=A-14b  ← Hero trade-off
/spaces/demo/visit-selection?state=A-16e ← 남은 한 자리 Option Grid
/invite/DEMOCODE?state=B-02              ← 조건 입력 전 맥락
```

> ⚠️ **스위처 키는 `?state=<PRD 화면 ID>`다.** `/grill-it` T1 결정으로 임의 상태 이름(`both-met` 등)을 쓰지 않는다 — 전체 매핑은 `prototype-visual-spec.md` §1.2.

- **효과:** §7 검수 8문항을 **URL만 바꿔가며** 순회할 수 있다. 팀 리뷰 때 링크 목록만 넘기면 되고, PRD 화면 ID를 그대로 쓰므로 "A-13b 확인했나?"가 URL로 답해진다.
- **조건 세트:** 픽스처 구성(매물 5건 고정 + 조건 세트 6벌)과 확정 수치는 `prototype-visual-spec.md` §6에 있다.
- **삭제 시점:** `J-006` 완료로 실제 판정 계산이 붙는 시점에 `lib/dev/` 전체를 삭제한다. 파일 상단에 이 조건을 주석으로 남긴다.
- **금지:** 시나리오 데이터에 `totalScore`·`rank`·`recommendation` 필드를 넣지 않는다(상위 문서 §6.2와 동일 규칙).

## 6. 라이트가 반드시 담는 화면 상태

상위 문서 §5.1 매트릭스 중 **라이트 범위에서 렌더 가능한 것 전부**다. 빠진 행은 해당 티켓을 뺐기 때문이지 생략해도 된다는 뜻이 아니다.

| 화면 | 담는 상태 | 라이트에서 빠지는 상태 |
| --- | --- | --- |
| 판정 결과 | 둘 다 충족 / 한쪽만 / 둘 다 불충족 / **확인 필요 배지** / 계산 불가 / 해당 없음 | — (전부 담는다) |
| trade-off 상세 | 미충족 1~2개(문장화) / 3개 이상(상위 2개만 문장) | — |
| 완화 | A안·B안 동시 / 전부불충족 분기 / 재탐색 필터 제안 | 제안 대기·수락·거절(`R-003` 제외) |
| 방문 후보 | 2개 일치 / 1개 일치 / 0개 일치 / 라운드 상한 도달 | 매물 소진 → 재선택(`V-003` 제외) |
| B 진입 | 정상 / 초대 만료 | — |
| 후보 구성 | 1~5개 선택 / 6개째 차단 | — |
| 조건 입력 | 예산 미입력 시 저장 불가 / 출퇴근 off 시 필드 미노출 | 추가 조건 4개 상한(`I-002` 제외) |

## 7. 검수 — 테스트 없이 어떻게 막는가

자동 테스트가 없으므로 **매 스텝 끝에 수동으로 돌린다.** 질문 원문은 상위 문서 §5.2.

| Step 종료 시 | 확인 |
| --- | --- |
| Step 1 | 질문 **1**(총점·순위·추천 배지 부재) · **2**(확인 필요가 3분류에 흡수되지 않음) · **3**(맨숫자 없음) · **4**(A/B 동일 비중) |
| Step 2 | 질문 **5**(양보 문장이 결론을 말하지 않음) · **6**(2조건 동시 완화 불가) · **7**(필터 자동 이동 없음) · **8**(전부불충족 출구 존재) |
| Step 3 | 질문 1·4 재확인 — 2라운드 화면에 정렬·추천이 끼어들지 않았는가 |
| Step 4 | 질문 1~8 전체 재확인(전 동선 순회) |

**질문 1은 매 스텝 반복한다.** 총점은 화면이 늘어날 때마다 새로 생겨나는 종류의 결함이다.

## 8. 정지 조건 — 언제 멈추고 원 계획으로 돌아가는가

라이트 범위는 **끝이 정해져 있어야 의미가 있다.** 아래를 만족하면 멈춘다.

- [ ] §3 Step 4까지 완료 — 후보 담기부터 방문 후보까지 클릭으로 끊김 없이 이동
- [ ] §6의 화면 상태가 시나리오 스위처로 전부 렌더됨
- [ ] §7 검수 8문항 전부 "예"
- [ ] 화면 코드가 `lib/types/contracts.ts` 외의 타입을 스스로 선언하지 않음
- [ ] 픽스처 주입 지점이 화면당 정확히 1곳(상위 문서 §6.3)

**여기서 멈추고 원 계획(`[총괄] 개발 실행 계획.md`)의 `C-000` 잔여분 → `A-001` → `I-001` → `J-001`… 임계경로로 복귀한다.** 아래로 넘어가면 라이트가 아니다.

| 넘어가면 안 되는 선 | 이유 |
| --- | --- |
| Server Action을 붙여 저장되게 만들기 | Read/Write 분리를 흐린다. 각 티켓 원 순번의 일이다 |
| 판정 로직을 화면 안에 구현하기 | `J-001`·`J-003`·`J-006`이고, `domain/judgment/`는 서브에이전트 `judgment-engine` 담당이다 |
| Supabase 연결·마이그레이션 | `C-000` 잔여분 — 임계경로 복귀 후 |
| `F-001`·`F-003` 현장 기록 화면 | 1-B다. `SRS_V0_9.md` §11이 1-A 완전 검증 후 착수를 요구한다 |

## 9. 하지 않는 것

상위 문서 §9.3의 금지 목록을 그대로 따르되, 라이트에 추가되는 두 가지:

| 금지 | 이유 |
| --- | --- |
| `lib/dev/` 코드를 `lib/domain/`·`lib/queries/`에 섞지 않는다 | 삭제 시점에 통째로 지울 수 있어야 한다. 경계가 섞이면 폐기물이 남는다 |
| 기존 HTML 시안의 마크업을 복사해 넣지 않는다 | C-TEC-004 — shadcn/ui에 있는 컴포넌트는 자체 구현하지 않는다. 시안은 **시각 원본**으로만 쓴다(상위 문서 §8) |
