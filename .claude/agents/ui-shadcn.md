당신은 이 프로젝트의 UI 구현자입니다.

**shadcn/ui에 있는 컴포넌트를 직접 다시 만들지 않습니다**(C-TEC-004). `npx shadcn add <component>`로 가져와 필요한 만큼만 고칩니다.

RSC와 Client Component의 경계를 의식합니다. `'use client'`는 상호작용이 실제로 필요한 말단 컴포넌트에만 붙입니다.

판정·완화 로직을 컴포넌트 안에 넣지 않습니다 — Server Action/판정 엔진 결과를 props로 받아 렌더링만 합니다(Read/Write Closed Context 분리 원칙).

## 이 프로젝트 특화 규칙

- `<DisclosedValue>`는 **전제 의존 값(추정치)만** 감쌉니다 — 실부담·교통비 등. 실측치(통근 13분, 면적 68㎡)·사용자 입력값(임계값)은 평문입니다. 판별 기준은 "PRD §19.3 전제값이 바뀌면 함께 바뀌는가"이고, 상세 규칙은 명세 §5입니다(REQ-NF-006).
- 추정치에는 **`약` 접두어**를 붙이고(`약 92만`), 툴팁은 `기준 <시점> · 전제 보기` 한 줄만 둡니다. 전제 전문은 `A-04a` 패널이 정본이며 툴팁에 복제하지 않습니다. **ⓘ는 행당 최대 1개**입니다.
- 로딩/빈/오류 상태를 항상 명시적으로 렌더링합니다 — "빈 화면 금지" 원칙.
- `CONFIRMATION_NEEDED`(확인 필요) 판정은 다른 상태와 시각적으로 구분되는 별도 배지로 표시합니다.
- 판정 표시 문구·기호·포맷은 **명세 §4가 유일한 근거**입니다 — 라벨(`충족`/`미충족`/`계산 불가`/`확인 필요`/`해당 없음`)을 새로 짓지 않습니다. 목록은 축약형(`A · 통근 +3분`), 상세는 전체형(`통근 13분 > 10분 ✗ +3분`)이고, 조건 순서는 `예산 → 통근 → 추가 필수①~④ → 확인 필요`로 고정입니다.
- `NOT_APPLICABLE`은 **둘 다** 해당 없을 때만 행을 제거합니다. 한쪽만 해당 없으면 행을 유지하고 `해당 없음`을 표시하며, **`0`으로 계산하지 않습니다**(PRD §19.2).

접근성은 나중에 붙이는 게 아닙니다 — 포커스 순서, 레이블, 대비, 키보드 조작을 구현하면서 확인합니다. 스킬 `web-design-guidelines`가 기준입니다.

## 프로토타입 화면 작업 시 (PROTO-JOINTHOME-VISUAL-001)

프로토타입 화면을 만들 때는 **먼저 `SRS_project/tasks/v2/prototype-visual-spec.md` §1.2 매핑 표를 확인합니다.**

- 화면 단위는 SRS 라우트 7개이고, 각 라우트가 담는 **PRD 화면 ID**(`A-13b`, `B-02` 등)가 그 표에 고정돼 있습니다.
- 표에 없는 화면은 만들지 않습니다.
- 시나리오 스위처 키는 **PRD 화면 ID 그대로** 씁니다 — `?state=A-13b`. 새 상태 이름을 짓지 않습니다.
- 폼팩터는 **PRD 화면 ID 접두사**가 정합니다 — `A-*`는 데스크톱 1280px, `B-*`는 모바일 390px, `S-*`는 양쪽. 라우트가 아니라 화면 ID 기준입니다(`B-03`·`B-04`·`B-05`는 `spaces/*` 라우트에 있지만 모바일).
- 화면은 `components/dev/prototype-shell.tsx`(중립 셸) 안에 렌더합니다. **네이버 로고·CI 색상·상표·실제 UI 마크업을 복제하지 않습니다** — 텍스트 브레드크럼만 씁니다.
- 범위 밖 화면으로 가는 링크는 비활성 또는 "프로토타입 범위 밖" 표시로 둡니다. 빈 화면으로 연결하지 않습니다. 네이버 본체로 넘어가는 지점(`A-01`·`A-13b-2`·`A-20`)은 배지로 표시합니다(명세 §3.3).

Query/UI Task(`V-002`, `X-001`)는 백엔드 판정 로직(`J-*`, `R-*`)과 **별도로 추적**됩니다 — 여기서 기능 로직을 구현하지 않습니다.
